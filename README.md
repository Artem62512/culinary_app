# Кулинарное веб-приложение

Приложение для расчёта ингредиентов, КБЖУ и стоимости блюд. Позволяет создавать рецепты, пересчитывать их под нужное количество порций и собирать корзину для покупок.

## 🚀 Текущий функционал (MVP)

- **Умный поиск продуктов**: Выбор ингредиентов через комбобокс с поиском по категориям и названиям.
- **Автоопределение единиц**: Система автоматически подставляет граммы, миллилитры или штуки (яйца, лук и т.д.) на основе названия продукта.
- **Защита от дубликатов**: Запрет на добавление одного и того же продукта в рецепт дважды.
- **Расчётное ядро**: Пересчёт ингредиентов под нужное количество порций, расчёт КБЖУ и стоимости блюда.
- **Корзина (как в маркетплейсах)**: 
  - Добавление ингредиентов одним кликом (с анимацией «улетания» в корзину).
  - Подсчёт общего КБЖУ и стоимости.
  - Копирование списка покупок в буфер обмена.
  - Очистка корзины.
- **Красивые уведомления**: Всплывающие toast-уведомления вместо стандартных `alert()`.
- **Управление рецептами**: Создание, просмотр и удаление рецептов.

## 🛠 Технологический стек

**Бэкенд:** Python 3.14, FastAPI, SQLAlchemy, SQLite, Pydantic.
**Фронтенд:** React 19, Vite 8, TypeScript 7, Tailwind CSS 4, shadcn/ui, TanStack Query, Motion (анимации), Sonner (уведомления).

## Запуск на Windows

ZIP-архив исходников содержит batch-файлы для запуска, но требует установленный Python 3.14 и Node.js 22. Первоначальная установка зависимостей выполняется с подключением к интернету.

1. Создайте виртуальное окружение и установите backend-зависимости из корня проекта:

   ```bat
   py -3.14 -m venv backend\.venv
   backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
   copy backend\.env.example backend\.env
   ```

2. Откройте `backend\.env` и задайте значения `APP_USERNAME` и `APP_PASSWORD`.
3. Установите frontend-зависимости:

   ```bat
   cd frontend
   npm ci
   cd ..
   ```

4. Дважды щёлкните `Culinary App.bat`, чтобы запустить backend и frontend вместе. Для раздельного запуска используйте `start_backend.bat` и `start_frontend.bat`.

В режиме разработки SQLite-файл создаётся локально в `backend\culinary.db` (если путь не переопределён в `.env`). Базы данных не включаются в ZIP-архив проекта.

В GitHub Actions:

1. В настройках репозитория включите GitHub Pages с источником **GitHub Actions**.
2. При push в ветку `main` страница-витрина публикуется из `docs/`.
3. Batch-файлы доступны в ZIP-архиве исходников. Workflow сборки Windows-установщика остаётся настроен на теги `v*`.

Для получения новых цен и данных КБЖУ во время работы требуется подключение к интернету; база, рецепты и корзина остаются на устройстве пользователя.


## Безопасность

Перед запуском backend настройте `backend/.env` по образцу `backend/.env.example`. API закрыт HTTP Basic авторизацией; без APP_USERNAME и APP_PASSWORD запросы к API отклоняются. Используйте HTTPS при любом сетевом доступе. Текущая модель авторизации — один общий владелец, а не полноценная многопользовательская система. Подробности: `backend/README_SECURITY.md`.

### Расчёт КБЖУ и ограничения точности

- Пищевая ценность продуктов каталога задаётся на 100 г.
- В рецепте значения суммируются по ингредиентам с известной массой (г/кг).
- Для мл/л и штук приложение не предполагает плотность или массу единицы автоматически: без этих данных показатель остаётся неполным.
- Отсутствующие макронутриенты не считаются нулевыми. API возвращает `null` для неполного итогового показателя, отдельно — `known_*` (известная часть), список недостающих данных и процент ингредиентов с полными данными.
- Показатель на 100 г рассчитывается от общей исходной массы ингредиентов и не учитывает испарение или впитывание влаги при приготовлении.

### Стоимость рецепта и корзины

- Стоимость рецепта считается отдельно по количеству ингредиентов для выбранного числа порций. Корзинные изменения цены не меняют расчёт рецепта.
- Цена предложения приводится к рублям за кг, литр или штуку; граммы/килограммы, миллилитры/литры и штуки рассчитываются пропорционально. Пересчёт объёма в массу не выполняется.
- Для стаканов, ложек, зубчиков, пучков, щепоток и «по вкусу» коэффициенты не предполагаются: такие позиции сохраняются, но их цена не рассчитывается.
- Приоритет подтверждённых предложений: ВкусВилл, Яндекс Лавка, Пятёрочка. Неизвестная цена отображается как отсутствующая, а частичная сумма сопровождается количеством позиций с известными ценами.
- Цену можно изменить только в текущей корзине либо отдельным действием добавить новое наблюдение в историю выбранного предложения. Корзинное изменение само по себе не меняет каталог.
- В корзине можно вручную задать размер и цену упаковки. При переключении режима цены количество ингредиента из рецепта остаётся неизменным; число необходимых упаковок рассчитывается отдельно.
- Для получения новых данных ВкусВилл используется существующий MCP-импортёр `backend/scripts/import_vkusvill.py`. Для других магазинов требуется подключить подтверждённый источник данных; приложение не генерирует предложения и цены.

### Проверка качества каталога

В каталоге продуктов отображается сводка качества. Для интеграций и диагностики доступен авторизованный read-only endpoint `GET /api/products/catalog/quality`. Он выявляет неполное КБЖУ, непроверенные записи, пустые категории и повторяющиеся названия. Дубликаты не удаляются и не объединяются автоматически, поскольку на продукты могут ссылаться рецепты.


### Единый каталог продуктов (этап 7)

Каталог универсальных ингредиентов хранится в SQLite и отдаётся через Backend API. Конкретные товары магазинов и история их цен хранятся отдельно и связываются с универсальным продуктом. Во frontend нет статического основного массива продуктов.

Для существующей базы перед обновлением сделайте резервную копию `backend/culinary.db`, затем выполните из папки `backend`:

```powershell
alembic upgrade head
python -m scripts.seed_catalog
```

Миграция `20261121_cart_price_overrides` добавляет к позиции корзины собственную цену и ссылку на выбранное предложение; цены каталога и существующие позиции при этом не удаляются.

Seed-скрипт идемпотентен: повторный запуск не создаёт дубликаты и не перезаписывает существующие названия, КБЖУ, пользовательские данные и связи. Для пустой базы сначала примените все миграции Alembic, затем запустите seed.
