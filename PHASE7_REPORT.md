# Этап 7 — единый каталог продуктов

Дата подготовки: 18.11.2026

## Статус

Backend-часть этапа реализована в рабочей копии проекта. Начальный каталог заполнен в SQLite. Frontend обновлён; синтаксическая проверка TypeScript/TSX выполнена, проверка TypeScript-компилятором прошла. Полная Vite production-сборка в Linux-среде не выполнена из-за отсутствующего Linux native binding пакета Rolldown; исходный архив содержит платформозависимые Windows-зависимости.

## 1. Универсальные продукты

- Добавлены поля `normalized_name`, `attributes` (JSON) и `status` в `products`.
- `attributes` предназначено для кулинарно значимых характеристик: жирность, сорт, часть туши, разновидность, способ обработки и другие параметры.
- Статусы: `active`, `inactive`, `archived`.
- Сохранены прежние поля КБЖУ, категории, группировки, источники и временные метки.
- Поиск использует нормализованное имя: Unicode NFKC, регистронезависимое сравнение, `ё/е`, игнорирование лишних пробелов и пунктуации.
- Поиск поддерживает частичное совпадение имени и синонимов; фильтрацию по категории и пагинацию.

## 2. Конкретные товары магазинов

Добавлены таблицы:

- `store_products` — SKU магазина, связанный с `products.id` через `universal_product_id`;
- `store_product_prices` — история цен с валютой, регионом, источником и датой наблюдения.

В `store_products` хранятся название SKU, производитель, бренд, магазин, размер упаковки и единица, штрихкод, ссылка, регион, JSON-характеристики и статус.

Существующая таблица `product_prices` сохранена для обратной совместимости. Старые 85 записей каталога и их ссылки не преобразовывались автоматически в SKU: для части записей не хватает достоверных производителя, бренда, упаковки и соответствия универсальному продукту. Автоматическое преобразование могло бы изменить смысл рецептов и цен.

Импортёр ВкусВилл переработан: новые выгрузки создают универсальный продукт и отдельный SKU магазина; повторные запуски находят SKU по `source/source_id`, обновляют данные источника и добавляют новые наблюдения цены. Сам сетевой импорт в рамках этой проверки не запускался.

## 3. Начальное наполнение SQLite

Добавлен `backend/scripts/seed_catalog.py` и набор `backend/app/services/catalog_seed_data.py`.

Наполнение охватывает все 13 категорий и включает базовые продукты, сорта и кулинарно значимые варианты обработки. Добавляются только названия, которых ещё нет после нормализации. Пользовательские названия, КБЖУ, категории и связи не перезаписываются. КБЖУ для новых позиций не выдумывается: пока нет подтверждённых значений, оно остаётся `missing`.

Результат первого запуска на предоставленной базе:

- всего 1 033 продукта;

## 4. API

Добавлены/расширены операции:

- `GET /api/products` — поиск, категория, статус, лимит и смещение;
- `POST /api/products/catalog/selection` — проверка набора выбранных ID с сохранением порядка и удалением повторов;
- `GET /api/products/store-products` — поиск SKU по универсальному продукту, магазину и названию;
- `POST /api/products/store-products` — создание SKU;
- `GET /api/products/store-products/{id}/prices` — история цен;
- `POST /api/products/store-products/{id}/prices` — добавление наблюдения цены;
- `PATCH /api/products/{id}/status` и `PATCH /api/products/store-products/{id}/status` — изменение статуса;
- существующие операции категорий и синонимов сохранены.

Новые SKU не используются как ингредиенты рецептов напрямую: рецепт продолжает ссылаться на универсальный `products.id`.

## 5. Интеграция цены

Сервис `app/services/pricing.py` объединяет старые цены универсального продукта и новые цены связанных SKU. Для расчёта стоимости использует последнюю пригодную цену в RUB/kg. Пересчёт для объёма и штук не выполняется без подтверждённой плотности или массы единицы.

## 6. Frontend

- Каталог остаётся API-driven: статического массива продуктов во frontend нет.
- Добавлена пагинация каталога по 100 позиций.
- Поиск в сопоставлении пользовательского ингредиента с каталогом стал удалённым и поддерживает большой каталог.
- В карточке универсального продукта добавлен просмотр и создание связанных товаров магазинов, добавление цены.
- Множественный выбор ингредиентов в рецепте остаётся через несколько строк ингредиентов; каждую строку можно удалить из состава.

## 9. Известные ограничения / следующие подзадачи

1. 948 новых универсальных продуктов пока без подтверждённых КБЖУ. Нельзя заполнять их приблизительными числами без источника.

3. Для импорта реальных SKU и цен нужен доступ к источнику магазина и проверка структуры его ответа; сетевой импорт здесь не запускался.
4. Стоимость из store SKU автоматически пересчитывается только для упаковок в граммах/килограммах и цен в RUB.

## Дополнение: раздельная стоимость рецепта и корзины

Последующее обновление добавляет расчёт стоимости в совместимых единицах: RUB/kg, RUB/liter и RUB/piece. Для универсального продукта выбирается подтверждённое предложение с приоритетом ВкусВилл → Яндекс Лавка → Пятёрочка; объём не преобразуется в массу без проверенного коэффициента.

Стоимость рецепта рассчитывается независимо от корзины. Переопределение цены корзины сохраняется в `shopping_list_items`; отдельное действие добавляет цену в историю `store_product_prices`. Для неизвестных цен API возвращает `null` при отсутствии известных позиций и отдельно перечисляет позиции без цены.

Миграция `20261121_cart_price_overrides` добавлена и применена к локальной базе после создания резервной копии `backend/backups/culinary.db.before_cart_price_overrides_20261121.bak`. Реальные цены не импортировались автоматически. Для ВкусВилл сохранён существующий MCP-импортёр; источники Яндекс Лавки и Пятёрочки требуют подтверждённого способа получения данных, прежде чем их можно включить.

Проверки после обновления: backend `pytest -q` — 52 passed; `npm run build` — успешно; Alembic head — `20261121_cart_price_overrides`.
