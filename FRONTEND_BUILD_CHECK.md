## Итог

Production-сборка **не подтверждена**. Проверка выявила, что в рабочей копии отсутствуют установленные npm-пакеты, включая `react`, `@types/react`, `typescript` и `vite`.

## Что проверено

- `frontend/package.json` и `frontend/package-lock.json` присутствуют.
- Корневые зависимости в lock-файле соответствуют декларациям `package.json`.
- Node.js: `v22.16.0`.
- npm: `10.9.2`.
- Перед попытками установки создана резервная копия БД: `backend/backups/culinary.db.before_frontend_dependency_repair_20261118.bak`.
- Выполнена установка `npm ci --no-audit --no-fund` с использованием `package-lock.json`.
- Установка не завершилась: обращения к `https://registry.npmjs.org/` завершались `EAI_AGAIN` (ошибка разрешения DNS/доступа к registry) и истекало время ожидания.
- После неудачной установки `npm run build` запущена для диагностики. TypeScript сообщил об отсутствии `react`, `react/jsx-runtime`, `@types/node` и других зависимостей. Большая часть последующих JSX/implicit-any ошибок является следствием отсутствующих типов и библиотек; по этому запуску нельзя достоверно судить о наличии ошибок в исходном TSX-коде.
- Неполная папка `node_modules`, оставшаяся после прерванной установки, удалена. Файлы исходников и lock-файл не менялись.

## Как завершить проверку на компьютере разработчика (PowerShell)

Откройте PowerShell в папке frontend проекта и выполните:

```powershell
npm ci --no-audit --no-fund
npm run build
```

Если `npm ci` снова завершается ошибкой DNS/сети, проверьте доступ к `https://registry.npmjs.org/`, DNS и настройки прокси. Не заменяйте `npm ci` на `npm update`: задача — установить зафиксированные версии из lock-файла, а не обновить зависимости.

При успешном `npm run build` Vite создаст `frontend/dist`. Только после этого можно считать production-сборку подтверждённой.
