# Переход на единый каталог ингредиентов

## Что изменено

- У каждого ингредиента рецепта теперь обязателен один `product_id`.
- `custom_name`, `matched_product_id` и `matching_status` удалены из активной модели, API и интерфейса.
- Неизвестный ингредиент можно создать прямо в форме рецепта как новый продукт каталога. Его КБЖУ остаётся пустым, пока значения не будут внесены.
- В форме рецепта можно выбрать найденный продукт вручную или создать новый.
- В карточке каталога добавлено редактирование КБЖУ на 100 г. Пустое поле означает неизвестное значение; статус `full` / `partial` / `missing` пересчитывается сервером.
- В расчёте рецепта и добавлении ингредиентов в список покупок используется только `product_id`.

## Что делает миграция

Миграция `20261121_unified_recipe_products`:

1. Для пользовательских ингредиентов ищет только точное совпадение нормализованного названия с названием продукта каталога.
2. Если найден ровно один продукт, привязывает ингредиент к нему.
3. Если совпадения нет, создаёт новый продукт с категорией «Другое» и пустыми значениями КБЖУ.
4. Не использует синонимы и приблизительное совпадение для автоматической привязки.
5. Игнорирует прежний `matched_product_id`: он мог указывать на неподходящий продукт.
6. Делает `recipe_ingredients.product_id` обязательным и удаляет три устаревших поля сопоставления.

Миграция сохраняет ID рецептов и ингредиентов, количество, `amount_text`, `amount_is_exact`, единицу измерения и примечание. Если обнаружится неоднозначное точное совпадение или ингредиент без названия и без `product_id`, миграция остановится с ошибкой.

## Важно перед запуском на своём компьютере

Архив не содержит `.env`, `.venv` и `node_modules`. Не удаляй и не перезаписывай свой `.env`: он может содержать настройки подключения и авторизации.

Если в локальной базе после создания приложенного архива появились новые рецепты или изменения, используй именно локальную базу и запусти миграцию на ней. Сначала сделай резервную копию:

```powershell
cd C:\Projects\CulinaryApp_phase7\CulinaryApp_phase7\backend
New-Item -ItemType Directory -Force .\backups | Out-Null
Copy-Item .\culinary.db ('.\backups\culinary.db.before_unified_catalog_' + (Get-Date -Format 'yyyyMMdd_HHmmss') + '.bak')
python -m alembic upgrade head
```

Если используешь нестандартный путь к базе в `.env`, сначала убедись, что резервная копия сделана именно для этой базы.

После обновления backend перезапусти его. Для frontend в PowerShell:

```powershell
cd C:\Projects\CulinaryApp_phase7\CulinaryApp_phase7\frontend
npm ci
npm run build
```

Backend-тесты:

```powershell
cd C:\Projects\CulinaryApp_phase7\CulinaryApp_phase7\backend
pytest -q
```
